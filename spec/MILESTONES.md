# MILESTONES — אלופי הכפל

**מסמכי בסיס:** `PRD.md`, `ARCHITECTURE.md`, `DESIGN.md`  
**מטרה:** פיתוח מדורג של אפליקציית Web בעברית (RTL), מותאמת למובייל וניתנת להתקנה כ-PWA, באמצעות Milestones עצמאיים וניתנים לאישור.

## סדר הפיתוח

| Milestone | תוצאה עיקרית | תלות |
|---|---|---|
| M1 — שלד אפליקציה וניווט | שלושת המסכים נגישים ומעוצבים במבנה בסיסי | אין |
| M2 — תרגול כפל עובד | תרגילים אקראיים, תשובות ושתי הזדמנויות | M1 |
| M3 — סבבים, ניקוד ומצבי סיום | 55 תרגילים, פסילה, ניצחון והתחלה מחדש | M2 |
| M4 — שמירה מקומית ומסך אודות מלא | שחזור סבב ושיא אישי, טבלת כפל מלאה | M3 |
| M5 — עיצוב סופי, PWA ופריסה | חוויית מובייל מעוצבת ואתר חי ב-GitHub Pages | M4 |

## M1 — שלד אפליקציה וניווט ✅

**מטרה:** להקים בסיס פועל שמאפשר לעבור בין שלושת המסכים, ללא יצירת מסכים או שירותים נוספים.

**מה יש לממש:**
- פרויקט React + TypeScript עם Vite, CSS Modules ו-RTL (Git Repository כבר קיים ומחובר ל-GitHub).
- שלושה מסכים ראשיים בלבד: **בית**, **תרגול**, **אודות**, עם סרגל ניווט תחתון קבוע הכולל שלושה יעדים ותוויות בעברית.
- מסך בית עם שם **"אלופי הכפל"**, איור הילד (`spec/assets/home-illustration.png`), כפתור **"בואו נתרגל!"** שמוביל לתרגול וכפתור משני **"אודות"**.
- מבנה בסיסי למסכי תרגול ואודות בהתאם ל-Wireframes ול-DESIGN; בשלב זה רכיבי התרגול יכולים להיות לא פעילים, עם הבחנה ברורה שאינם ממומשים עדיין.
- התאמת פריסה ראשונית למובייל, אזורי לחיצה ברורים וכיווניות נכונה של טקסט עברי וביטויים מתמטיים.

**תוצר מצופה:** אפליקציה שנפתחת מקומית ומאפשרת לנווט בין שלושת המסכים ולחזור לבית בלי רענון עמוד.

**Definition of Done:**
- [ ] `npm run dev` מציג את האפליקציה ללא שגיאות Runtime; TypeScript ו-Build עוברים.
- [ ] סרגל הניווט מציג בדיוק **בית / תרגול / אודות**, מסמן יעד פעיל ומעביר למסך המתאים.
- [ ] כפתור **"בואו נתרגל!"** פותח את מסך התרגול.
- [ ] הממשק בעברית וב-RTL, ואין גלילה אופקית בלתי רצויה בפריסת טלפון טיפוסית.
- [ ] אין מסכי ניווט נפרדים עבור ניצחון או פסילה ואין Backend/Database.

## M2 — תרגול כפל עובד ✅

**מטרה:** לספק זרימת משתמש שלמה של הצגת תרגיל, הזנת פתרון וקבלת משוב, כולל ניסיון שני.

**מה יש לממש:**
- יצירת מאגר 55 זוגות גורמים קנוניים בתחום 1–10 ובחירה אקראית ללא חזרה על תרגיל שכבר נפתר באותו סבב; `3×7` ו-`7×3` שקולים, אך `5×4` ו-`2×10` שונים.
- הצגת תרגיל אחד, שדה קלט מספרי שמפעיל מקלדת מספרית במובייל וכפתור **"בדוק תשובה"**.
- Validation: קלט ריק או לא תקין אינו צורך ניסיון; בדיקה נכונה מוסיפה הצלחה ומציגה הודעה קצרה לפני מעבר אוטומטי לתרגיל הבא.
- טעות ראשונה: הודעה על ניסיון אחד שנותר, ניקוי השדה ושמירת אותו תרגיל; טעות שנייה: סיום התרגול במצב פסילה בסיסי (עיצוב הסיום והניקוד המלא יושלמו ב-M3).
- ניהול מצב סבב באמצעות React Context + `useReducer`, כך שניווט בין מסכים לא מאפס את התרגיל או מספר הניסיונות.

**תוצר מצופה:** ילד יכול לפתור רצף תרגילים ולקבל משוב נכון על הצלחה או טעות, עד פסילה.

**Definition of Done:**
- [ ] בדיקה אוטומטית מאשרת בדיוק 55 זוגות ייחודיים; החלפת סדר גורמים אינה יוצרת כפילות.
- [ ] בחירה אקראית אינה מחזירה תרגיל שכבר נפתר בסבב; פתרונות בעלי אותה תוצאה אך גורמים שונים נשארים נפרדים.
- [ ] תשובה נכונה מציגה הודעת הצלחה קצרה ומעבירה לתרגיל חדש ללא לחיצה נוספת.
- [ ] טעות ראשונה אינה מחליפה תרגיל; שדה התשובה מתרוקן ומוצגת הודעת ניסיון נוסף.
- [ ] טעות שנייה מסיימת את הסבב; קלט ריק/לא תקין אינו צורך ניסיון.
- [ ] מעבר לבית או לאודות וחזרה לתרגול שומר על התרגיל והניסיון שנותר.
- [ ] בדיקות Vitest ו-React Testing Library מכסות את מקרי הליבה לעיל.

## M3 — סבבים, ניקוד ומצבי סיום

**מטרה:** להשלים את מחזור המשחק עם ניקוד, סיום בהפסד, ניצחון ואפשרות להתחיל מחדש.

**מה יש לממש:**
- ניקוד נוכחי ככמות התרגילים שנפתרו בסבב, נקודה אחת לכל תרגיל; תצוגה במסך התרגול בפורמט **"12 מתוך 55"**.
- לאחר שתי טעויות באותו תרגיל: מצב סיום בתוך מסך התרגול, כותרת **"הסבב הסתיים"**, הצגת ניקוד, כפתור **"נסו שוב!"** וכפתור **"חזרה לבית"**.
- לאחר פתרון כל 55 התרגילים: מצב ניצחון בתוך מסך התרגול, כותרת **"כל הכבוד!"**, ניקוד **55 מתוך 55**, כפתור **"התחל סבב חדש"** וכפתור **"חזרה לבית"**.
- כפתור **"התחל מחדש"** במהלך תרגול, בקשת אישור וביטול ללא שינוי הסבב; אישור יוצר סבב חדש בניקוד 0.
- שיא אישי בזיכרון האפליקציה, המתעדכן כשהניקוד עולה מעל השיא הקודם; שמירתו הקבועה תתווסף ב-M4.

**תוצר מצופה:** משחק שלם מקצה לקצה במהלך הפעלה אחת, עם תוצאות ברורות והתחלת סבב חדש.

**Definition of Done:**
- [ ] כל תשובה נכונה מוסיפה בדיוק נקודה אחת; טעות ראשונה אינה מוסיפה או מאפסת נקודות.
- [ ] אחרי שתי טעויות מופיעים ניקוד הסבב וכפתור **"נסו שוב!"**, ואין התחלה אוטומטית של סבב חדש.
- [ ] אחרי 55 פתרונות נכונים מופיע מצב ניצחון, בלי ניסיון לבחור תרגיל 56.
- [ ] כפתורי סבב חדש מאפסים ניקוד, ניסיונות ורשימת תרגילים שנפתרו.
- [ ] ביטול אישור **"התחל מחדש"** שומר בדיוק על מצב הסבב.
- [ ] מצבי הסיום הם חלק ממסך התרגול ולא יעדי ניווט נוספים; סרגל הניווט נשאר עקבי.
- [ ] בדיקות אוטומטיות מאמתות את כל מעברי המצב ואת חישוב הניקוד והשיא.

## M4 — שמירה מקומית ומסך אודות מלא

**מטרה:** לאפשר לילד לעזוב ולחזור לאותו סבב, ולעיין בשיא אישי ובטבלת הכפל.

**מה יש לממש:**
- שמירה ב-`localStorage` של הסבב הפעיל והשיא האישי בלבד, כולל תרגיל נוכחי, תרגילים שנפתרו, ניקוד, ניסיונות שנותרו ומצב סיום אם קיים.
- שחזור אוטומטי לאחר Reload, סגירת חלון ופתיחה מחדש; Versioning בסיסי למבנה הנתונים ובדיקת תקינות לפני שחזור.
- טיפול במצב שבו `localStorage` חסום או פגום: המשך תרגול בזיכרון והודעה ברורה בעברית על כך ששמירת ההתקדמות אינה מובטחת.
- מסך **אודות** עם הסבר קצר, **הניקוד הנוכחי**, **השיא האישי** וטבלת כפל מלאה 1–10, שנכנסת ברוחב הטלפון ללא גלילה אופקית; העמוד גולל אנכית.
- וידוא ששיא אישי אינו נמחק בעת התחלת סבב חדש, אך מחיקת נתוני האתר עשויה להסירו.

**תוצר מצופה:** האפליקציה זוכרת את המשחק והשיא באותו מכשיר; מסך אודות שימושי כדף עזר.

**Definition of Done:**
- [ ] לאחר פתרון מספר תרגילים, רענון או סגירה ופתיחה משחזרים ניקוד, תרגיל, רשימת תרגילים שנפתרו ומספר ניסיונות.
- [ ] שחזור לאחר טעות ראשונה מאפשר רק ניסיון אחד נוסף באותו תרגיל.
- [ ] השיא האישי מתעדכן כאשר נשבר, ונשמר אחרי התחלה מחדש ופתיחה חוזרת.
- [ ] מסך אודות מציג ניקוד נוכחי ושיא אישי התואמים למצב המשחק, וטבלת 10×10 עם ערכים נכונים וכותרות שורה/עמודה.
- [ ] נתוני אחסון חסרים, פגומים או חסומים אינם גורמים לקריסת האפליקציה; מוצג משוב מתאים אם השמירה אינה זמינה.
- [ ] אין חשבון משתמש, סנכרון ענן, Database או API חיצוני.

## M5 — עיצוב סופי, PWA ופריסה

**מטרה:** להשלים את המראה שהוגדר ב-DESIGN ולספק אפליקציה מותקנת ונגישה בכתובת ציבורית.

**מה יש לממש:**
- החלת השפה החזותית של `style-guide.png` ו-`mockups.png`: צבעים, היררכיית טיפוגרפיה, כפתורים, כרטיסים, אייקונים ואיור בית; התאמה למבנה ה-Wireframes ולדרישות ה-PRD במקרה של סתירה.
- עיצוב סופי לשלושת המסכים ולמצבי תרגול/הצלחה/טעות/פסילה/ניצחון, כולל Focus נגיש, ניגודיות, קריאות תרגילים, Safe Areas והתנהגות כשהמקלדת פתוחה.
- Web App Manifest בעברית (`name`, `short_name`, `lang`, `dir`, `display`, `start_url`, `scope`) ואייקוני PWA מקומיים; ללא Offline caching. רק אם נדרש להתקנה בדפדפן היעד — Service Worker מינימלי מסוג NetworkOnly, ללא Precache.
- חיבור GitHub Repository ל-GitHub Pages באמצעות GitHub Actions: Type Check, בדיקות, Build ו-Deployment אוטומטי מ-`main`; התאמת Vite `base` לנתיב האתר.
- בדיקת זרימות מלאות בכתובת ה-Production ובמכשיר נייד, לרבות התקנה כ-PWA ושחזור נתונים אחרי פתיחה מחדש.

**תוצר מצופה:** גרסה סופית מעוצבת, זמינה ב-HTTPS, עם Deployment אוטומטי והתקנת PWA במכשיר תומך.

**Definition of Done:**
- [ ] שלושת המסכים והמצבים נראים עקביים עם DESIGN, ללא מסכים או פיצ'רים חדשים; מסך אודות כולל את טבלת הכפל גם אם חסרה בתמונת Mockup.
- [ ] הטקסטים בעברית וב-RTL; ביטויים מתמטיים מוצגים בסדר הנכון; שדה הקלט מפעיל מקלדת מספרית.
- [ ] אין חפיפה בין סרגל הניווט, תוכן המסך והמקלדת בטלפון שנבדק; טבלת הכפל קריאה וניתנת לעיון.
- [ ] `npm run build`, Type Check וכל הבדיקות האוטומטיות עוברים.
- [ ] Push ל-`main` מפעיל GitHub Actions ופורס אוטומטית אתר תקין ב-GitHub Pages ב-HTTPS.
- [ ] ה-Manifest והאייקונים נטענים בנתיב הפריסה, והאפליקציה ניתנת להתקנה בפועל לפחות בדפדפן מובייל תומך שנבדק.
- [ ] אין מימוש ייעודי של Offline; אין Backend, Database, חשבונות או שירותי מעקב.
- [ ] בגרסה הפרוסה נבדקים: תרגול, ניסיון נוסף, פסילה, ניצחון, התחלה מחדש, ניווט, שיא אישי ושחזור לאחר פתיחה מחדש.

## Development Execution Rules — הוראות מחייבות ל-AI המפתח

1. **לפתח לפי הסדר:** M1 → M2 → M3 → M4 → M5. אין לדלג על Milestone או להתחיל עבודה על הבא לפני אישור.
2. **בסיום כל Milestone לעצור:** להציג למשתמש מה מומש, כיצד להפעיל או לפתוח את התוצר, ואילו בדיקות בוצעו מול כל סעיף ב-Definition of Done, כולל תוצאות והסתייגויות.
3. **להמתין לאישור מפורש:** אין להתחיל בפיתוח ה-Milestone הבא עד שהמשתמש מאשר את הקודם במפורש.
4. **לשמור על תוצר עובד:** כל Milestone יסתיים בגרסה שניתן להריץ ולבדוק. רכיב שטרם מומש יסומן ככזה, ולא יוצג כפיצ'ר עובד.
5. **לכבד את מסמכי המקור:** PRD קובע פונקציונליות; ARCHITECTURE קובע Stack ותשתית; DESIGN קובע שפה חזותית. אין להוסיף דרישות או שירותים ללא אישור.
6. **שינויים ב-Git:** לשמור את קוד המקור ב-GitHub; לפני פרסום גרסה חדשה להציג תוצאות בדיקות. לאחר הפעלת ה-Deployment האוטומטי ב-M5, כל עדכון ל-`main` עשוי לפרסם גרסה חיה, ולכן אין לדחוף שינויים שלא אושרו.

**הבהרה טכנית:** המערכת משתמשת ב-`localStorage` בלבד; אין Supabase, אין Database Migrations ואין צורך בהקמת סביבות Database נפרדות.
